## Toil Offloading（默认启用）

遇到可切分的实质工作时默认委派：根 agent 是**强而慢**的模型，subagent 是
**便宜而快**的模型。多一个子任务的边际成本是便宜模型的时间，而不是根 agent 的上下文。

**判据不是「是否机械」，而是「能否切出一个自包含、验收条件可观察的子任务」。**
能切就能派，包括实现、重构、写测试。留在根 agent 的是无法写成合同的部分 ——
它本身就是决策：哪个设计对、真实需求是什么、交付是否可接受。

- 根 agent 保留：需求澄清、任务分解、架构与接口决策、合同撰写、集成、
  风险分级、验收裁定、冲突解决、破坏性或外部改动
- 委派出去：侦察与上下文收集、实现、重构、批量改动、数据提取、产物生成、
  写测试、跑聚焦验证、按验收标准做独立 review
- 用 `subagent` 工具（`afang-subagent` 扩展）；默认并行，
  扇出宽度 64 任务 / 16 并发；同一批里的写入合同不得重叠
- **可用 agent**（均为便宜模型）：`scout` 侦察 / `planner` 定计划 /
  `worker` 实现（可写）/ `reviewer` 独立评审（只读）
- **模型分级是 session 级设置**，在 `~/.common_shell_setup_local.sh` 用
  `PI_SUBAGENT_PROVIDER` / `PI_SUBAGENT_MODEL` 声明（当前 dspro + deepseek-flash[1m]）。
  优先级：环境变量 > agent frontmatter > 当前 session 模型。
  因此**不要在 agent frontmatter 固定模型**，否则会产生第二套失效的真相源。
- **廉价 subagent 的安全性来自合同，不来自模型**：弱模型让它*决策*才危险，
  让它*执行*是安全的。所以先在根 agent 确认方案、写成具体合同，再让 subagent 出量。
  不要写「分析这个模块并修复问题」。诊断、根因分析、架构权衡留在根 agent。
- **按风险分级验收，而不是习惯性全审**：低风险（格式化、改名、机械扫）根 agent
  看 diff 即可；中风险跑聚焦测试，改动大时派 `reviewer`；高风险（安全、鉴权、
  数据变更、并发、权限）必须 `reviewer` + 根 agent 复核。
  验收深度看**爆炸半径**，不看 diff 大小。
- **`reviewer` 是便宜模型**，能可靠抓「合同说 X、代码做 Y」这类具体偏差、
  漏掉的边界、明显缺陷；但它审不出深度错误。高风险改动的判断力在根 agent，
  不以 reviewer 通过作为验收依据。
- 委派前必须写清合同（目标、输入路径、所有权边界、已定方案、验收标准、返回格式）；
  不要只发一句话目标
- **不适用于**：一句话能答完的问题、纯聊天/解释、单个小编辑、需要连续上下文
  推理的紧耦合改动 —— 这类直接自己做更快

完整方法论见 `toil-offloading-pi` skill，遇到非平凡委派时读取。
