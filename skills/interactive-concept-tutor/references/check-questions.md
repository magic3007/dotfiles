# 检验性提问模板

两处用到提问:**Phase 0** 上课前探测水平,**Phase 3** 讲完后检验是否真懂。下面分开给。

---

## Phase 0 — 上课前:水平探测

目的是定位"最近发展区"—— 已知什么、下一步能接住什么。问 2–4 个,等用户回答再动手。

### 通用三问

1. **背景锚点**:"你对 <前置概念> 熟到什么程度?能不能一句话说说它是干嘛的?"
   - 探出前置是否牢固,决定从哪一层起讲。
2. **目标深度**:"你想达到哪种程度 —— (a) 有个直觉就行 (b) 能自己在纸上推导 (c) 能动手把它实现出来?"
   - 直接决定 notebook 里 code cell 的比重和推导的细致度。
3. **触发点**:"你是在读某篇论文/某段代码时卡住了吗?具体卡在哪?"
   - 锚定真实场景,避免讲一堆用户不关心的东西。

### 用回答校准

- 前置薄弱 + 只要直觉 → 多画图、多类比,少推导,code cell 以"可视化现象"为主。
- 前置扎实 + 要能实现 → 快速略过基础,重点放推导 + 完整可跑的实现 cell。
- 有明确论文/代码触发点 → 大纲直接对齐那个场景的符号和记法。

---

## Phase 3 — 讲完后:检验是否真懂

沿四个维度提问,能答上来才算真懂,而不是"看着眼熟"。

### 1. 直觉维度(能用大白话解释)
- "用一句不带公式的话,说说 <概念> 到底在干嘛?"
- "如果去掉 <某个组件>,会发生什么?"

### 2. 推导维度(能自己推)
- "从 <上一步> 出发,你能推出 <这一步> 吗?卡在哪一步说一下。"
- "这个公式里的 <某项> 为什么是这个形式,换成别的行不行?"

### 3. 边界维度(知道什么时候不成立)
- "什么情况下这个方法会失效 / 退化?"
- "它和 <相邻方法> 的关键区别是哪一点?"

### 4. 代码对应维度(公式 ↔ 实现对得上)
- "notebook 里这一行代码,对应公式里的哪一项?"
- "如果我把 <某变量> 改大 10 倍,输出会怎么变?先猜再跑。"

## 范例题库:线性 Attention / KDA

配合 `phase1_linear_attention.ipynb` 这类教学 notebook 使用。

### Phase 0 探测
- "softmax attention 为什么是 O(n²)?你知道瓶颈在哪个矩阵吗?" —— 探 attention 基础。
- "你熟悉 RNN 的隐状态递推吗?" —— 线性 attention 的递推形式就是一个 RNN,这是关键桥梁。
- "你是想理解线性 attention 的原理,还是要能自己实现一遍 KDA?"

### Phase 3 检验
- **直觉**:"线性 attention 靠什么把 O(n²) 降成 O(n)?" (kernel trick 把 softmax 拆开,状态可累加)
- **推导**:"从直接求和的形式,怎么改写成一步步递推的形式?" (维护一个累加状态 S)
- **边界**:"朴素线性 attention 没有遗忘会出什么问题?RetNet→Mamba→GLA→KDA 各补了什么?"
- **代码对应**:"KDA 那段里 `S = alpha*S`、`u = v - k@S`、`S += outer(k*beta, u)`、`o = q@S` 分别对应算法的哪一步?"(遗忘 / 误差 / 写回 / 读出)
- **预测再验证**:"把遗忘因子 alpha 调到接近 0,状态范数 ‖S‖ 会怎么变?先猜,再跑 cell 看。"
