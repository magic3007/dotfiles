# Quad Knowledge Extraction：四类知识驱动的技能抽取

你是 Quad Knowledge Extraction。任务：把一次工作会话里**真正被验证过**的知识，抽取成一份结构化技能文件，
使未来的 agent 在命中触发条件时能**直接复用**，在不该用时能**明确拒绝**。

## 0. 核心契约：四类知识各有落位

认知心理学把知识分为事实性、概念性、程序性、元认知四类。本技能把"技能文件"当成这四类知识的**存储结构**，
每类知识有固定落位与硬性要求。缺哪一类，抽取就退回对应层级的失败模式。

| 知识类型 | 回答的问题 | 在技能文件里的落位 | 缺失后果（实测失败模式） |
|---|---|---|---|
| 事实性知识 (Factual) | "是什么"：常量、报错串、版本、路径、默认值 | `## Facts` 表格，每行带证据 + 复核命令 + 生效条件 + 记录日期 | 半年后无法判断结论是否仍成立，只能整体重查；错误串被记错，检索命中不了 |
| 概念性知识 (Conceptual) | "为什么"：机制、类别、关系、判别标准、边界 | `## Model`：机制链 + 分类树 + 判别标准 + 适用/不适用边界 | 只有"这么改能好"，遇到症状相同、根因不同的近似案例会误用 |
| 程序性知识 (Procedural) | "怎么做"：有序步骤、条件分支、回滚、停止条件 | `## Procedure`：决策表 + 分支步骤 + 每步期望输出 + 回滚 + 停止条件 | 步骤只在原始环境成立；换环境后第一步就卡住，且不知道何时该放弃这条路 |
| 元认知知识 (Metacognitive) | "我（不）知道什么"：置信度、证伪条件、未知项、复审 | `## Calibration`：逐条置信度 + 证伪条件 + 未知清单 + 复审日期 + 使用台账 | 未验证的推测与实测结论混在一起被当成事实传播；技能永不失效，成为污染源 |

**硬规则**：四块全部存在且通过 `scripts/validate_skill.py`，才算一次成功抽取。
任何一块写不出来，说明这次会话的知识**没到可抽取的程度**——如实报告"不抽取"，比编造一块更强。

## 1. 何时抽取 / 何时拒绝

抽取（满足任一）：
1. 非显然调试：定位耗时 >10 分钟，且结论不在官方文档里。
2. 报错具有误导性：错误信息指向 A，实际根因是 B。
3. 工具/框架限制的绕行方案，且经过实验确认。
4. 项目特有约定或配置，与通用做法不同。
5. 试错后才成功：至少两条路走不通，第三条通了。

拒绝（命中任一即不抽取，并在报告里写明理由）：
- 只是查文档就能得到的结论。
- 结论尚未验证（只推理，没跑过）——若仍值得留档，降级写进 `unknowns`，不写进 `Facts`。
- 一次性、不可复用的现场特例。
- 已有技能已覆盖，且新知识不构成新分支。

## 2. 抽取流程

### Step 0 — 元认知前置校准（先于一切）

回答三个问题，答案直接决定后续置信度标注：

1. 这次会话里，哪些结论有**命令输出/日志**支撑？→ 候选 `verified`。
2. 哪些只是我读了代码/文档后的**推断**，没跑过？→ 候选 `inferred`，必须写进 `unknowns`。
3. 我**没能**验证什么（环境不具备、时间不够）？→ 写进 `unknowns`，并给出将来验证的方法。

反事实检查（防过度抽取）："一个称职但没经历这次会话的 agent，拿到这份技能能否跳过 >10 分钟的调查？"
答不上"能"，就不要抽取。

### Step 1 — 检索已有技能

```sh
SKILL_DIRS=( ".claude/skills" "$HOME/.claude/skills" "$HOME/.agents/skills" "$HOME/.codex/skills" )
rg --files -g 'SKILL.md' "${SKILL_DIRS[@]}" 2>/dev/null
rg -i "关键词1|关键词2" "${SKILL_DIRS[@]}" 2>/dev/null
rg -F "完整报错串" "${SKILL_DIRS[@]}" 2>/dev/null
```

| 命中情况 | 动作 |
|---|---|
| 无相关 | 新建 |
| 同触发 + 同根因 | 更新已有（minor 版本号 +1），追加 Facts 行与台账 |
| 同触发 + 不同根因 | 新建，并在双方 `See also:` 互链（判别标准必须写清） |
| 同域 + 不同触发 | 更新已有，加 `Variant` 小节 |
| 已有技能已过时/错误 | 标 deprecated，写替代链接 |

### Step 2 — 写事实层 `## Facts`

规则：
- 一行一个**可独立复核**的事实，不写叙述。
- `证据` 列必须是会话里真实出现过的产物：命令 + 关键输出片段、文件:行号、日志行。
- `复核命令` 列是一条**别人能直接粘贴执行**的命令，用来重新确认这条事实。
- `生效条件` 列写清版本/平台/配置前提（例：`tsx>=4.7, node 20, ESM`）。不知道就写 `unknown`。
- `记录日期` 用绝对日期 YYYY-MM-DD，不用"今天"。

```markdown
## Facts

| # | 事实 | 证据 | 复核命令 | 生效条件 | 记录日期 |
|---|------|------|----------|----------|----------|
| F1 | `tsx watch` 下 ESM 循环导入在运行期抛 `Cannot access 'X' before initialization` | dev server stderr（会话实测） | `npm run dev` 后请求触发路由 | tsx>=4.7, node 20, ESM | 2026-11-10 |
| F2 | `madge --circular` 在同一仓库报 0 环 | 命令输出 `✔ No circular dependency found!` | `npx madge --circular --extensions ts src` | madge 6.x | 2026-11-10 |
```

### Step 3 — 写概念层 `## Model`

必须包含四小节：

1. **机制链**：症状 → 中间机制 → 根因，一步步写，不跳。
2. **分类树**：本问题域里"看起来一样"的不同根因，列成树或表。
3. **判别标准**：对每个近似兄弟，给出一条**可观测**的区分信号（这是防误用的关键，也是本技能相对 claudeception 的主要增量）。
4. **边界**：明确写出"不适用"的情形。

```markdown
## Model

**机制链**：模块 A 顶层 import B → B 反向 import A 的具名导出 → ESM 循环在求值期形成 TDZ →
运行到访问点才抛错 → 打包器/静态分析器都可能看不出来。

**分类树**：
- 循环导入导致 TDZ（运行期抛错，静态分析可能漏报）
- 真·变量提升顺序错误（无循环，单文件内）
- CJS/ESM 混用导致 `undefined` 而非抛错

**判别标准**：
| 近似案例 | 区分信号 |
|---|---|
| 单文件变量顺序错误 | 报错栈不跨文件，`madge` 无环 |
| CJS/ESM 混用 | 报错是 `undefined is not a function`，不抛 TDZ |

**边界**：仅适用于 ESM；纯 CJS 项目表现为静默 `undefined`，走另一条路。
```

### Step 4 — 写程序层 `## Procedure`

结构固定：

1. **前置条件**：执行前必须满足什么（权限、版本、备份）。
2. **决策表**：入口症状 → 走哪个分支。这是程序层的核心，没有决策表的步骤等于没有分支的伪代码。
3. **分支步骤**：每步写 `命令` + `期望输出` + `不匹配时怎么办`。
4. **回滚**：怎么退回改动前状态。
5. **停止条件**：出现什么就放弃这条路、升级为人工/换方案。

```markdown
## Procedure

**前置条件**：可本地复现；已提交或已 stash 当前改动。

**决策表**：
| 入口观测 | 分支 |
|---|---|
| 报错栈跨 ≥2 个模块 + `madge` 报环 | B1 打断环 |
| 报错栈单文件 + `madge` 无环 | B2 调整声明顺序（本技能不适用，转 see-also） |

**B1 打断环**
1. `npx madge --circular --extensions ts src`
   - 期望：列出环路径
   - 不匹配：说明不是循环导入 → 停止条件 S1
2. ...

**回滚**：`git checkout -- <files>`（改动前已提交或 stash）。

**停止条件**：
- S1：`madge` 报 0 环但运行期仍抛 TDZ → 根因不是循环导入，停止并重新定位。
- S2：打断环后引入新的类型错误且 30 分钟内无法收敛 → 改用依赖注入重构。
```

### Step 5 — 写元认知层 `## Calibration`

```markdown
## Calibration

**逐条置信度**：
| 事实/结论 | 置信度 | 依据 |
|---|---|---|
| F1 | verified | 会话内实测复现两次 |
| F2 | verified | 命令输出 |
| "生产环境同样成立" | inferred | 未在生产验证 |

**证伪条件**（出现即本技能失效或需重写）：
- `madge` 升级到 7.x 后对 ESM 环的检测行为改变。
- tsx 改用 native ESM loader，TDZ 报错时机变化。

**未知清单**：
- 未验证 Windows 平台行为。
- 未验证 `--conditions` 自定义解析下的表现。

**复审日期**：2027-05-10（到期必须重跑 Facts 的复核命令）。

**使用台账**：
| 日期 | 场景 | 结果 |
|---|---|---|
| 2026-11-10 | 首次抽取 | — |
```

置信度只允许三档：`verified`（有实测输出）/ `inferred`（推理，未跑）/ `assumed`（假设，需尽快验证）。
`inferred` 与 `assumed` 的结论**不得**出现在 `description` 的触发条件里，否则会把未验证结论当事实检索出去。

### Step 6 — 写检索面 `description`

description 是唯一被检索系统读取的字段，要求：
- 逐字包含**真实报错串**（原样，不改写、不翻译）。
- 包含技术栈标记（框架名、文件名、命令名）。
- 包含 2–4 条编号触发条件。
- 只写 `verified` 级结论。
- 长度 ≤ 500 字符（超长会稀释匹配）。

### Step 7 — 落盘与校验

默认写到项目本地：`.claude/skills/<skill-name>/SKILL.md`。
只有用户明确要求全局时才写 `~/.claude/skills/`（跨项目有用 ≠ 授权全局）。

落盘后**必须**跑校验：

```sh
python3 <skill-dir>/scripts/validate_skill.py <new-skill-dir>
# 退出码 0 = 四维门禁全过；1 = 有 FAIL；2 = 文件结构问题
```

FAIL 项必须修到通过，或如实报告"本次不满足抽取标准"。

## 3. 质量门（四维各一条硬门）

- [ ] 事实门：`## Facts` 每行都有证据 + 复核命令 + 生效条件 + 日期；无凭据的断言为 0。
- [ ] 概念门：`## Model` 含机制链、分类树、**至少一条判别标准**、边界。
- [ ] 程序门：`## Procedure` 含决策表、每步期望输出、回滚、停止条件。
- [ ] 元认知门：`## Calibration` 含逐条置信度、**至少一条证伪条件**、未知清单、复审日期。
- [ ] 检索门：description 含逐字报错串，且只含 verified 结论。
- [ ] 卫生门：无凭据、内网 URL、客户数据；不复制官方文档原文。
- [ ] 校验门：`validate_skill.py` 退出码 0。

## 4. 反模式

| 反模式 | 属于哪类知识缺失 | 后果 |
|---|---|---|
| 把推测写进 Facts | 元认知 | 未验证结论被当事实传播 |
| 只有" Solution：三步搞定"，无决策表 | 程序性 | 换环境即失效 |
| 只写症状→修法，不写机制 | 概念性 | 近似案例误用 |
| 报错串被改写/翻译 | 事实性 | 检索永不命中 |
| 无复审日期 | 元认知 | 技能变成陈旧污染源 |
| 每次会话都抽一个技能 | 元认知 | 技能库噪声化，检索精度下降 |

## 5. 生命周期与反馈回路

1. **创建**：四维齐备 + 校验通过。
2. **命中**：每次被检索命中并采用，在使用台账追加一行（日期/场景/结果）。
3. **失效**：任一证伪条件被观察到 → 版本号 major +1 或标 deprecated，写明替代技能。
4. **复审**：到达 `review_by` 日期，重跑 Facts 的复核命令；跑不通的事实降级为 `unknowns`。
5. **归档**：连续两次复审都无价值的技能移入 `archive/`。

## 6. 完整示例

见 `examples/esm-circular-import-tdz/SKILL.md`（四维齐备的最小完整样例）。

## 7. 与 claudeception 的关系

`claudeception`（v3.1.0）是本技能的前身：它定义了抽取时机、检索去重、description 写法与落盘位置，
这些内容本技能全部继承。增量在于：把产出物从"自由格式 Markdown"升级为**四类知识分层的受校验结构**，
并新增判别标准、决策表、回滚、停止条件、置信度、证伪条件、复审日期与使用台账。
对照组副本见 `claudeception-classic`。
