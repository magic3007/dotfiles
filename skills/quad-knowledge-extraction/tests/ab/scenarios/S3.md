# 会话记录 S3：GitHub Actions 上测试失败，本地永远通过（node_modules 缓存污染）

## 环境

```
$ node -v
v20.11.1
$ npm -v
10.8.2
```

`.github/workflows/ci.yml`（节选）：

```yaml
jobs:
  test:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - uses: actions/cache@v4
        with:
          path: node_modules
          key: ${{ runner.os }}-nm-${{ hashFiles('package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-nm-
      - run: npm test
```

## 现象

PR 上 CI 失败：

```
> acme-api@2.4.0 test
> vitest run

FAIL  test/billing.spec.ts
AssertionError: expected 1999 to be 2000
 ❯ test/billing.spec.ts:42:20
```

本地 `npm test` 连续 20 次全绿。CI 上重跑同一个 commit 也是必失败（不是 flake）。
但**上一个 commit 在 CI 上是绿的**，而这次 PR 只改了 `test/billing.spec.ts` 的一个断言文案。

## 调查过程

尝试 1（失败）：怀疑断言写错。`git diff` 确认只改了字符串字面量，没动数值。排除。

尝试 2（失败）：怀疑时区/浮点。`TZ=UTC npm test` 本地仍绿。排除。

关键观测：

```
$ npm ls @acme/pricing
acme-api@2.4.0
└── @acme/pricing@1.9.0
```

本地是 `@acme/pricing@1.9.0`。CI 里加一步 `npm ls @acme/pricing` 打印出来是 `@acme/pricing@1.8.3`。

```
$ grep -n '"@acme/pricing"' package.json package-lock.json | head
package.json:12:    "@acme/pricing": "^1.9.0",
package-lock.json:141:  "node_modules/@acme/pricing": { "version": "1.9.0", ...
```

lockfile 里是 1.9.0，与 package.json 一致。

原因链：`actions/cache` 的 `restore-keys` 是**前缀匹配**，只要 key 前缀命中就恢复旧缓存，
即使 `hashFiles('package-lock.json')` 已经变了。于是 CI 恢复了上一次（1.8.3 时代）的整个
`node_modules` 目录，而 workflow 里**没有** `npm ci` 这一步——`setup-node` 的 `cache: 'npm'`
只缓存 npm 的下载缓存（`~/.npm`），不负责安装。于是 1.8.3 被直接用上了。

验证（在 CI 里临时加两步）：

```
$ # step: npm ls @acme/pricing  → @acme/pricing@1.8.3
$ # step: rm -rf node_modules && npm ci && npm ls @acme/pricing
@acme/pricing@1.9.0
$ # 之后 npm test 通过
```

## 最终修复（已验证）

```yaml
      - uses: actions/cache@v4
        with:
          path: ~/.npm
          key: ${{ runner.os }}-npm-${{ hashFiles('package-lock.json') }}
      - run: npm ci
      - run: npm test
```

即：只缓存 npm 下载缓存，并显式 `npm ci`；删掉 `restore-keys` 前缀兜底。

验证：连续 6 个 commit（含两个只改测试文件的 commit）CI 全绿；
本地 `rm -rf node_modules && npm ci && npm test` 也绿。

## 顺带发现（未验证）

- 没验证 pnpm（`actions/setup-node` 的 `cache: 'pnpm'`）是否有同样问题，直觉是 pnpm 的
  store 与 node_modules 布局不同但机制类似，**没实测**。
- 没验证 GitHub 托管 runner 缓存的淘汰策略（7 天/10 GB）会不会让问题自愈。
- 没验证 `restore-keys` 保留但改成 `npm ci` 是否也足够（我直接删了，没做这个对照）。

## 另一个看起来一样的报错（不同根因，供对照）

另一次 CI 失败信息是：

```
npm ERR! code EINTEGRITY
npm ERR! sha512-... integrity checksum failed when using sha512
```

那次 `package-lock.json` 里锁的 tarball integrity 与 registry 上实际发布的对不上——
上游把 `1.9.0` 这个版本**重新发布**了。删 `restore-keys`、加 `npm ci` 都无效；
真正的修法是 `npm cache clean --force` + 锁定到未被重发的版本（或用 `npm ci --prefer-online`）。
症状（"CI 挂、本地绿"）一样，根因完全不同。
