# 会话记录 S1：pnpm monorepo 里 vitest 报 Cannot find module '@acme/core'

## 环境（会话开始时采集）

```
$ node -v
v20.11.1
$ pnpm -v
9.12.3
$ npx vitest --version
vitest 2.1.8
```

仓库结构：

```
apps/web/           # vite + vitest 测试
packages/core/      # 被依赖的内部包，package.json 里 "name": "@acme/core"
pnpm-workspace.yaml
```

## 现象

`apps/web` 下跑测试，报错（完整 stderr，原样）：

```
FAIL  src/lib/cart.test.ts [ src/lib/cart.test.ts ]
Error: Failed to load url @acme/core (resolved id: @acme/core). Does the file exist?
 ❯ src/lib/cart.ts:1:23
      1 | import { priceCart } from '@acme/core'
```

但 `pnpm --filter @acme/web dev` 起开发服务器完全正常，浏览器里页面能跑。
`pnpm -w build` 也成功。

## 调查过程

尝试 1（失败）：以为是 workspace 没链接。

```
$ ls -la apps/web/node_modules/@acme/
lrwxrwxrwx 1 u u 32 Nov  3 10:12 core -> ../../../../packages/core
$ pnpm -F @acme/web why @acme/core
dependencies:
@acme/core 0.3.1
```

软链存在，依赖解析没问题。排除。

尝试 2（失败）：以为是 `packages/core` 没构建产物，于是在根目录跑 `pnpm -w build` 后重跑测试，报错一字不变。排除。

关键观测：

```
$ cat packages/core/package.json
{
  "name": "@acme/core",
  "version": "0.3.1",
  "main": "./src/index.ts",
  "types": "./src/index.ts"
}
$ cat packages/core/tsconfig.json | head -20
{ "compilerOptions": { "composite": true, "outDir": "dist" } }
```

`@acme/core` 的 `main` 直接指向 `./src/index.ts`（源码，不是 dist）。

```
$ cat apps/web/vitest.config.ts
import { defineConfig } from 'vitest/config'
export default defineConfig({ test: { environment: 'jsdom' } })
```

`apps/web/vitest.config.ts` 里没有任何 alias / plugin 配置。
`apps/web/vite.config.ts` 里有：

```
$ grep -n "tsconfigPaths\|alias" apps/web/vite.config.ts
3:import tsconfigPaths from 'vite-tsconfig-paths'
7:  plugins: [react(), tsconfigPaths()],
```

即：`tsconfigPaths()` 插件只挂在 `vite.config.ts` 上，而 vitest 在存在 `vitest.config.ts` 时**不会**合并 `vite.config.ts`。

```
$ cat apps/web/tsconfig.json | grep -A3 paths
    "paths": { "@acme/core": ["../../packages/core/src/index.ts"] }
```

## 最终修复（已验证）

在 `apps/web/vitest.config.ts` 里同样挂上插件：

```ts
import tsconfigPaths from 'vite-tsconfig-paths'
export default defineConfig({ plugins: [tsconfigPaths()], test: { environment: 'jsdom' } })
```

验证：

```
$ pnpm -F @acme/web test
 ✓ src/lib/cart.test.ts (7 tests) 312ms
 Test Files  1 passed (1)
$ rm -rf apps/web/node_modules/.vite && pnpm -F @acme/web test
 ✓ src/lib/cart.test.ts (7 tests) 298ms
```

清掉 vite 缓存后重跑仍通过，确认不是缓存假象。

## 顺带发现（未验证）

同事说他在 CI 上也遇到同样报错，我**没有**在 CI 环境复现过，不确定 CI 是不是同一个根因
（CI 用的是 `pnpm -F @acme/web test --run`，没有 jsdom 差异，但我没跑过）。
另外我没验证过 `vitest --workspace`（vitest 2.x 的多包模式）下的行为。

## 后来遇到的另一个看起来一样的报错（不同根因，供对照）

另一个仓库里 `import { x } from '@acme/core'` 也报 `Cannot find module '@acme/core'`，
但那里 `packages/core` 的 `package.json` 是 `"main": "./dist/index.js"` 且带
`"exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } }`，
`dist/` 根本没构建（被 `.gitignore` 了，CI 里没跑 build）。那次是**构建顺序**问题，
不是 alias 问题——`vitest.config.ts` 里加 tsconfigPaths 完全无效。
